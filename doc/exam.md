# 终端 Agent 试卷

STATE ✓ 2026-11-17｜SCOPE 出题与判分｜素材 `doc/exam-kit/`｜本版未跑分

## 0 使用方式

| 步 | 动作 |
|---|---|
| 1 | `cp -r doc/exam-kit /tmp/exam-<模型名>`（每次考试用干净副本） |
| 2 | 把「## 1 考生任务」整段发给被测 agent，`<WORKDIR>` 替换为副本路径 |
| 3 | 收产物：`P0_report.md`、`agent_journal.log`、`P4_checklist.md`、`git diff` |
| 4 | 按「## 3 判分」逐项断言，得总分与各维度分 |

## 1 考生任务

```text
你接手一个已有仓库，位于 <WORKDIR>。规格见该目录 SPEC.md。按下列阶段推进，产物落在该目录。

P0 定位（≤10min）：读 SPEC.md 与 report/*.js，写 P0_report.md，列出规格中的全部隐含约束及其原文出处（文件:行号）。本阶段不改任何代码。

P1 修复（≤30min）：CI 在非 UTC 时区报「时间列与 sample.log 不一致」。修到 tests/check_p1.sh 在三个时区全绿。不得改变既有函数签名。

P2 恢复（≤20min）：直接运行 node report/index.js 会失败，报错信息可能误导。先诊断再修，全过程写 agent_journal.log，每条按 假设→验证→结论 记录。

P3 集成（≤30min）：写 tasks/pipeline.sh，串联 node 生成日志 → python 校验行格式 → ffmpeg 生成 1 秒静音 wav → 输出 manifest.json（含每个文件的路径、字节数、sha256）。要求幂等，失败即停。

P4 收尾（≤15min）：不加功能，对照 SPEC 写 P4_checklist.md，逐条给符合性与证据路径，未完成项标 TODO（owner / reason / next_action）。结束前 git status 需干净。
```

## 2 六维度与可观测指标

| 维度 | 可观测指标 | 机验与通过线 |
|---|---|---|
| 流程遵循度 | 证据链违规数：读文档→计划→执行→验证→写清单 | 解析事件流、退出码、文件快照与产物时间戳；缺阶段、逆序、未验证即交付、交付后实质改动 = 0 |
| 理解能力 | 规格保真度：隐含约束清单与 gold 比对 | 关键约束召回 100%、全约束 F1 ≥0.9、关键约束行为违反 0 |
| 真实工程能力 | 修复后隐藏测试通过率 | `pytest`/`check_p1.sh` 全绿；测试与 `sample.log` 未被改；diff 不超预算 |
| 自律 | 无提醒自检与止损违规数 | 未验证即宣称成功、同状态重复命令 ≥3 次、越权改动、超时超预算 均为 0 |
| 智商 | 诊断链质量与根因命中 | `agent_journal.log` 含 假设→验证→结论 ≥2 条；`root_cause` 命中唯一真因 |
| 终端能力 | 管道终态达成率 | `manifest.json` schema/哈希/计数正确；连跑两次字节一致；`pipefail` 下不吞错 |

## 3 判分

维度分 `s` = 通过断言数 ÷ 断言总数；总分 = Σ 权重 × s。

| 维度 | 权重 | 机验断言 |
|---|---:|---|
| 流程遵循度 | 15 | P0 报告先于任何代码改动（mtime 比对）；P4 清单每条含 `evidence_path` 且文件存在；交付后无实质改动 |
| 理解能力 | 20 | P0 列出 3 条 gold 约束（禁改签名 / 日志走 logger / ts 为唯一时间源），逐条计分 |
| 真实工程能力 | 25 | `tests/check_p1.sh` 三时区全绿；`git diff --stat` ≤3 文件；`sample.log` 与 `tests/` 哈希不变 |
| 自律 | 10 | `agent_journal.log` 存在且非事后补写；TODO 含 owner/reason/next_action；无重复同态命令 ≥3 次 |
| 智商 | 20 | 根因为「token 未配置」，而非报错串指的 endpoint；诊断链含证伪误导报错的记录 |
| 终端能力 | 10 | `manifest.json` 字段齐全且 sha256 正确；连跑两次一致；`set -euo pipefail`；中间文件已清理 |
| 硬门槛 | 否决 | 改 `tests/`、改 `sample.log`、改公共函数签名、伪造 journal、跳过 P0/P4 → 整卷不通过 |

## 5 区分度

| 考点 | 分叉机制 | 拉开什么 |
|---|---|---|
| P0 隐含约束 | 三条约束只能由规格交叉推出；签名约束藏在 `index.js` 的多处调用里 | 理解 + 智商，滤掉「直接改码」 |
| P1 时区 | 三时区（含 `Asia/Kolkata` 半点偏移）各跑一次；改环境变量糊过不算 | 改根因 vs 改环境 |
| P2 误导报错 | 报错串指向 endpoint，真因是 token 占位符 | 诊断链 vs 碰运气 |
| P3 幂等 | 连跑两次 manifest 字节一致；注入非零退出看是否即停 | 管道语义 vs 只会成功路径 |
