# 联网搜索（Tavily 四账号聚合池）

STATE ✓ 2026-10-24 ｜ SCRIPT `search.py`（同目录，`chmod 700`）｜ REF `memory/Tavily账号池-限流实测与选路设计.md`
SCOPE Tavily Search API 的吞吐、退避与额度择优；不含 crawl/extract/map

## CMD
```bash
cd ~/.config/term_agent/skill
./search.py "query"                          # 默认 basic / 5 条
./search.py "query" -m 10 -d advanced -a -s  # 深度搜索 + LLM 答案 + 摘要
./search.py -q qs.txt -m 3 -j                # 批量并发，输出 JSON
./search.py --stats                          # 各账号剩余额度 / 窗口 / 冷却
./search.py --reset                          # 清冷却与失败计数（保留额度记账）
./search.py --refresh-quota --stats          # 强制刷 /usage（受 10 次/10 分钟限流）
```

## ARG
| 参数 | 默认 | 约束 |
|---|---|---|
| `query` / `-q 文件` | — | 多条即并发；文件每行一条 |
| `-d` | `basic` | `basic`(1 credit) `advanced`(2) `fast` `ultra-fast` |
| `-m` | 5 | 1–20 |
| `-t` | `general` | `general` `news` `finance` |
| `-r` | 空 | `day` `week` `month` `year` |
| `-a` / `-s` / `-j` / `-v` | 关 | 答案 / 摘要 / 原始 JSON / 调试到 stderr |
| `--rpm` | 95 | 每 key 每分钟上限；官方 100，留 5% 余量 |
| `-c` | 0=自动 | 自动值 = `目标rps×2.2+1`（4 key→14）；单请求延迟约 2s |
| `--target-rps` | 6.0 | 仅影响自动并发 |
| `--max-wait` | 90 | 单请求最长等待；超时 exit 3 |
| `--reset` | — | 清 cooldown/fails/bad，不动 remaining |

## EXIT
| 码 | 含义 | 动作 |
|---|---|---|
| 0 | 全部成功 | — |
| 1 | 有请求失败（`errors` 非空） | 读 stderr；429/额度耗尽见 FAIL |
| 2 | 参数错（无 query / 无 key） | 看 `--help` |
| 3 | 全部 key 限流或冷却，等待超 `--max-wait` | 降低批量或加 `--max-wait` |

## EV
| 字段 | 含义 |
|---|---|
| `n` / `errors` | 成功条数 / 错误列表（含 query 原文） |
| `elapsed` / `rps` | 墙钟秒 / 有效吞吐（(n-1)/跨度，突发期可远高于持续上限） |
| `results[i]` | 原样 Tavily 响应 |
| `--stats` 的 `remaining` / `cooldown_s` / `win` | 剩余额度 / 冷却剩秒 / 窗口内已用次数 |
| `agg_rps` | `--rpm × key 数 / 60`，持续吞吐上限 |

## FAIL
| 现象 | 原因 | 动作 |
|---|---|---|
| 全部 401/403 | key 失效或被删 | 换 key；该 key 自动冷却 1h |
| 大量 429 | 单 key 超 100 RPM，或 `--rpm` 被调过 100 | 降 `--rpm`；查 `--stats` 的 `cooldown_s` |
| 持续 rps < 3 | 并发不足（单请求约 2s） | `-c 14` 或 `--target-rps 6` |
| `remaining` 明显小于实际 | 本地记账未刷 `/usage` | `--refresh-quota`（每 key 最快 62s 一次） |
| 结果某 key 一直不用 | 剩余额度低于 50 被降权 | 正常；`--stats` 确认 |
| 标题被截断 | `-s` 摘要按 400 字符截断 | 用 `-j` 取原始 JSON |

## RULE
| 约束 | 值 |
|---|---|
| 单 key 限流 | 100 RPM（官方 dev=prod），脚本默认按 95 计 |
| 聚合持续上限 | 4 key × 95 RPM ÷ 60 = **6.33 rps**（`--rpm 100` → 6.67） |
| `/usage` 限流 | 10 次/10 分钟 → 缓存 TTL 600s + 单 key 间隔 ≥62s，禁循环调用 |
| 429 处置 | 优先 `Retry-After`，缺省 60s，按 `×2^n` 退避至上限 300s；该 key 冷却期间请求转其它 key，不整体 sleep |
| 选路 | 剩余额度最高优先；同分按最久未用（轮转）；在途惩罚 `4×inflight`；剩余 <50 降权 |
| 状态文件 | `.search_state.json`（0600），只存 key 哈希与额度，不存明文 key |
| key 来源 | 脚本顶部 `KEYS` 或 `.search_keys`（每行一个，600）或环境变量 `TAVILY_KEYS` |
| 测试 | `TAVILY_BASE` 可指向本地 mock，零额度验证 429/选路 |
