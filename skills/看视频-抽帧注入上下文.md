# videowatch — 视频 → 有序时间戳帧 → 进上下文

## 何时用
- 用户发视频链接/文件并问"讲了什么 / 画面是什么 / 这段怎么样"
- 需要读视频里的画面、字幕、代码、操作步骤
- **不要靠猜或让用户口述**；抽帧自己看

## 一条命令
```bash
python3 ~/.config/term_agent/skill/videowatch.py "<URL 或本地路径>"
```
退出码：`0` 已落地 / `3` 已排队（看守自动补插） / `1` 错 / `4` 回执图数不符 / `5` 关键帧全为空场（拒绝注入）

## 机制（4 步，顺序固定）
1. **取源**：URL → `yt-dlp -f bv*[height<=720]`，落 `~/.cache/videowatch/<sha1(src)前10>/src.mp4`；同 URL 重跑复用不重下
2. **降采样**：`ffmpeg -vf fps=<自适应>,scale=W:H` → `f1/f00001.jpg`。基础帧率按时长自适应：**<30s→5fps、<120s→2fps、其余 1fps**（短视频 1fps 会漏掉 1s 内的闪现内容）
3. **变帧检测**：逐帧缩 `64×36` 灰度，与**上一保留帧**（不是上一帧）求 `ImageStat(difference).mean`；首帧必留，`≥thr` 留；超 `max-frames` 按分数 top-N 保序
4. **组织+注入**：`out/t<毫秒>_i<序>.jpg`（6 位补零，字典序=时间序；时刻= 帧索引/fps）→ `ctxinject.py inject -w` 一条消息塞 N 图 → 宿主 `_img`（800 长边 + 216 色）→ `image_url` 进 `mem_hist`

## 参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `--thr` | 6.0 | 相邻保留帧灰度均差阈值（0-255）。调大=只要大变化 |
| `--max-frames` | 16 | 硬上限，超限按分数 top-N 保序 |
| `--budget` | 150000 | 注入 token 预算。超了自动降长边 480→360→300→240→180，仍超则时间轴均匀裁帧 |
| `--long` | 480 | 抽帧长边；源更小则不放大 |
| `--max-sec` | 900 | 时长闸门，超了报错不硬跑 |
| `--no-inject` | | 只出图 |
| `--quiet` | | 不唤醒宿主，排队注入 |

## 成本（宿主 216 色 PNG，实测）

> **2026-10-22 口径变更**：宿主 `MAXLONG` 已由 800 改为 **512**（并给 image_url 带 `detail:"low"`）。
> 当前模型 `deepseek-v4.1-flash` 实测**每图 prompt_tokens 封顶 ~1045**（512→235、800→473、1024→703、1344→1045），下方旧表是 **CC/Claude 口径**，与现役计费无关，仅作历史参考。
> 连带：`--long 640` 现在会被宿主再压回 512，**调大长边换清晰度已无效**；要小字清楚只能裁 ROI 后单独发。

| 画面类型 | 长边 | 单帧 token |
|---|---|---|
| 纯色/UI 型 | 480 | 0.3k |
| 真实画面 320×176 | 原生 | 10k |
| 真实画面 1080p | 480 | **18.7k** |
| 1080p | 360 / 300 / 240 / 180 | 11k / 8k / 6.3k / 4k |
连续色调（影视/游戏）最贵，纯 UI 便宜 30 倍。16 帧 @480 ≈ 300k token → 默认 budget 150k 会自动降到 300 档。

## 必知失败模式
1. **RUN 内注入必然 `deferred: tool_calls 未收尾`** —— 宿主末条是带 `tool_calls` 的 assistant。看守每 2s 重试，tool 结果补齐后 **3~4s 自动补插**。
   → **抽帧那一轮看不见图，下一轮才看见，这是正常行为，不要重复跑**（会插多条 user 消息）。
2. 帧路径**不能含空格**（ctxinject 空格分隔多图）；本脚本命名 `t%06d_i%02d.jpg` 天生安全。
3. `/tmp` 不可写（Termux/proot）→ 产物一律 `~/.cache/videowatch/`。
4. 第 n 帧（1 基）≈ **n-1 秒**；`fps` 取 t≥k 的首帧，1fps 下误差 ≤1s。
5. 纯音频/损坏文件：probe 取不到 `v:0` 直接报错，不会硬抽黑帧。
6. **禁止在放大图上估成本**：拿 320×176 源 `scale` 到 480 测出的数字虚高 2 倍。估成本源分辨率必须 ≥ 目标档。

## 实测基线（2026-10-22｜ffmpeg 9.0.2 / Pillow 13）
| 样本 | 结果 |
|---|---|
| 三色段 8s 640×360 | 8→3 帧，**精确命中 0s/3s/6s** |
| 纯灰静止 10s | 10→**1 帧**（不误报） |
| testsrc2 运动 6s | 6→4 帧 |
| 1080p 60s | 42 命中→16 帧，全链路 **3 秒** |
| `--max-frames 2` | 6→2 帧，0s/4s **保序** |
| 注入 3 帧 300 长边 | image_url×3，27.2k token，牌子文字仍可读 |

## 调参口诀
| 症状 | 动作 |
|---|---|
| 帧太多 / 太贵 | `--thr 8~12` 或 `--max-frames 8` |
| 小字看不清 | 裁 ROI 单独注入（宿主长边封顶 512，`--long` 调大无效） |
| 长视频 | `--max-sec 1800 --max-frames 12` |
| 只想拿图不进上下文 | `--no-inject` |

## 产物
```
~/.cache/videowatch/<hash10>/
  src.mp4 | f1/f%05d.jpg（1fps 全量） | out/t<秒>_i<序>.jpg | manifest.json
```
`manifest.json` = 源尺寸/时长/阈值/帧表（每帧含 `t` 毫秒、`sec` 秒、`i` 原始帧索引），二次分析直接读它，不必重跑 ffmpeg。

## 失败模式（2026-10-22 补｜细小笔画/局部动效会漏检）
7. **thr 在缩略图上算，占画面 <2% 的笔画会整段漏掉**：实测黑底红色手写笔画（占 1.1%），290×640 缩略图上帧差 < 4 → 6 帧评为"静止"，只保留 t=0 的**全黑首帧**，注入出去的图与内容无关。
   → 判断"画面是不是真静止"前先看**首帧均值**：均值 <2 且后续帧均值变高 = 后出现的内容，必须重抽。
   → 遇此类内容直接用 `--thr 1 --max-frames 8`，或按时间段手工抽全分辨率帧（`-ss 秒 -frames:v 1`）后单独注入。
8. **亮块≠文字**：先按颜色/灰度掩膜确认笔画色（本例纯红 255,0,6），再排掉录屏工具栏图标（底部 y>2000 的一排符号含红色圆点，会污染 bbox）。
9. **灰度高差 = 盲区**：红 (255,0,0) L≈76.2 与 CSS green (0,128,0) L≈75.1 几乎同亮度，纯色互切在灰度上"零变化"，检测不出。这类内容（同亮度换色、色块闪烁）只能靠降 `--thr` 或按秒定点抽帧。
10. 结论口径：用户问"写了什么"是在问**看图**，不是问像素统计。抽帧→注入→直接读图回答；本地掩膜/ASCII 只用于选帧与去干扰，不要拿它替代看图。
