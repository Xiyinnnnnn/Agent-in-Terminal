# 视觉注入 — 图 → 活跃上下文

SCRIPT `~/.config/term_agent/skill/ctxinject.py`
SCOPE 上游取图（截屏/抽帧/下载/生成）→ 下游用 `inject` 送进宿主。通道语义/退出码/代价见《运行时上下文注入.md》。

## CMD
```bash
S=~/.config/term_agent/skill/ctxinject.py
python3 $S inject --pid PID -w "标注文本" /abs/a.png /abs/b.png
python3 $S auto   --pid PID
```

## SOURCE
| 目标 | 命令 |
|---|---|
| 当前屏 | `python3 $S auto --pid PID` |
| 屏 → 文件 | `python3 $S shot -o /abs/x.png` |
| 已有图片 | `inject --pid PID -w "t" /abs/x.png` |
| 视频某刻 | `ffmpeg -ss 3 -i v.mp4 -frames:v 1 /abs/f.jpg` |
| 视频关键帧 | `videowatch.py`（见该技能） |
| 网络图 | `curl -sL -o /abs/x.png URL` |
| 生成图 | 存盘 → `inject` |
| 历史截图 | `ls -t ~/.cache/ctxinject/shot_*.png` |
| 文档内图 | 解包/转码后 `inject` |

路径须为目标进程可读的**同一文件系统绝对路径**；proot 拼出的 `/root/...` 宿主不可见。

## ADMIT（四条，脚本写死）
| # | 规则 | 违反后果 |
|---|---|---|
| 1 | 后缀 ∈ `.png .jpg .jpeg .gif .webp` | 该参数当文本，静默无图 |
| 2 | 文件存在 | 整批 `exit 1`，一条不注 |
| 3 | 路径无空格 | 被切成两个参数 → `no_such_image` |
| 4 | 仅位置参数算图 | 选项值不算 |

转码：
```bash
python3 - /abs/in.bmp /abs/out.png <<'PY'
import sys;from PIL import Image
Image.open(sys.argv[1]).convert("RGB").save(sys.argv[2])
PY
```

## BATCH
`inject --pid PID -w "t" a.png b.png c.png` → 1 条 user 消息含 3 个 `image_url`。
逐张注入 = N 条消息 + N 次唤醒 + 压缩边界移动 N 次。
上限：600 图/请求；≥15 图时上游单边 8192→4096。
`content` 顺序 = 参数顺序，文本恒在最前。

## RENDER（宿主处理链，决定清晰度与成本）
`_img()` → 长边压至 **512**（`MAXLONG`）→ 量化 216 色（`QCOL`）→ `detail:"low"`

| 输入 | 实际进入模型 | 每图 token |
|---|---|---|
| 1272×2800 整屏 | 233×512 | 233 |
| 长边 ≤512 | 原尺寸，不放大 | ≤233 |
| 长边 2048 | 仍 512，多余字节丢弃 | 233 |
| — | 1024 档 | 703 |
| — | 封顶 | ≈1050 |

小字可读性只随**裁切**提升，不随放大提升：
```bash
python3 - <<'PY'
from PIL import Image
im=Image.open("/abs/shot.png"); im.crop((300,1200,1000,1560)).save("/abs/roi.png")
PY
```
ROI 长边取 512 上下。坐标未知时：先注整屏定位，再注 ROI（2 条消息）。

## WHEN（落地时点）
| 宿主状态 | 结果 |
|---|---|
| idle、末尾已收尾 + `-w` | 0.1s 级落地，本轮可见 |
| 跑 RUN 中 | 必 `defer`，`exit 3`，0.1–15s 补插 → 下一轮可见 |
| 末尾 `assistant.tool_calls` 未收尾 | `tail_ok()` 拒插，收尾后补 |

## VERIFY
`exit 0` 后读 `ev:ok.d`：
| 字段 | 判据 |
|---|---|
| `hist_len` | 较上次 +1 |
| `content` | 含 `["image_url",n]` 且 `n>3000` |
| `img` | `[true,bytes]` 单图 |
| `imgs` | `[N,total_bytes]` 多图 |
| `skip` | `dup` = 已落地，算成功 |

终判：下一轮能否描述图内容。不能描述或只得"1张图" → 违反 ADMIT 之一。

## FAIL
| 现象 | 原因 | 动作 |
|---|---|---|
| `err:no_such_image` | 路径错/含空格/proot 路径 | `readlink -f` 后重发 |
| `exit 0` 无 `image_url` | 后缀非白名单 | 转 png |
| `image_url` 长度过低 | 图极小或当文本 | 查后缀与字节数 |
| `exit 2` | 缺 `--pid` | `hosts` 取值 |
| `exit 3` | 宿主忙 | WAIT，勿重跑 |
| 下一轮见 `[图]` | 已过压缩边界 | 重注并当轮出结论 |
| `no_adb_device` | adb 掉线/多设备 | `--device` |
| 全黑帧 | 息屏 | 点亮重截 |

## RULE
- 单次注入至多 1 条 user 消息；批量不逐张。
- 注入后须在本轮出结论（图不过压缩）。
- 不可为"更清楚"提高 `--long`。
- 注入即历史变更，`--pid` 必填，误注入不可撤回。
